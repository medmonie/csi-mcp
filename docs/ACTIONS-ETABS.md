# ETABS MCP actions (server 0.18.0)

Generated by tools/gen_docs.py from server/catalog.py and server/actions.py - do not edit by hand.

Call the `etabs` tool with `action` and `params`. With `CSI_MCP_SPLIT=1` the read actions are on `etabs_read` and the edit actions on `etabs_edit`.

> This server works with ETABS only (params.software is filled in; ETABS, SAP2000 and SAFE each have their own server). Reads attach to the running ETABS by themselves. ETABS: models are story-based; points, frames and areas carry a label and a story (get_objects takes story). Grids come from grid systems (get_grids), levels from get_stories. Story drifts, story shears, pier and spandrel forces are ETABS results (get_results). Older models pad story names with spaces: compare trimmed names. Column local axes vary from model to model: read them before calling a moment M2 or M3. ETABS meshes floors and walls with its own options, which are not in the API; joint patterns and surface pressure do not exist in ETABS (use uniform area loads, per strip for a load that varies). Joints at the Base level without a restraint are held fixed in the analysis (measured): build members that must deflect above the Base level. User spectrum / time-history functions and the RS / modal-history case options (combinations, steps) go through the program's database tables (other rows kept); these cases use the model's modal damping (0.05 by default).
>
> UNITS: every action that reads or writes numbers takes params.units (default kN_m_C = kN, m, C; also Ton_m_C, N_mm_C, kN_mm_C, kip_ft_F ... 16 CSI presets). The action sets those units, works, then puts the user's display units back. Always state the units in answers.
>
> DESIGN: Claude never chooses design codes, combinations, preferences, overwrites, sections, loads or limits; they come from the designer or the model. Design runs the program's own engine with the code set in the model or named by the designer (get_design_settings first, and state the code, combinations and units in answers). If something is missing, ask the user.
>
> LOCKED MODELS: a model with analysis results is locked. Changing it needs allow_unlock: true, which DELETES the results. Never send allow_unlock: true unless the user agreed in this conversation; a locked model answers 'confirmation_required' instead.
